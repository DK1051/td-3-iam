### 1b. Extra review of the whole diff

**B1 — bug (must fix, cheap): every export file is wrapped in an extra array.** `export-config.ps1` line 66:

    ConvertTo-Json -InputObject $Items -Depth 10 -AsArray | Set-Content -Path $path -Encoding utf8

Passing an array with `-InputObject` and also using `-AsArray` wraps it a second time. I tested this offline in pwsh 7.6.7:
- two items → `[[{"a":1},{"a":2}]]`
- one item → `[[{"a":1}]]`
- empty → `[[]]`

The stub run of the real script showed the same thing: `conditional-access-policies.json` held `[[{"Id":"p1",…},{"Id":"p2",…}]]`.
Fix: remove `-AsArray` and keep `-InputObject`. That gives `[…]`, `[{"a":1}]` and `[]`, which is correct in all three cases. The pipeline form (`$Items | ConvertTo-Json -AsArray`) is not a good alternative, because it writes nothing at all for an empty list.
No acceptance criterion tests the JSON shape, so this is not an AC FAIL. It should still be fixed before Eojin runs the script.

**B2 — minor:** the script exits 0 and prints "Done." even when every export failed. Each failure is printed (`<name>: FAILED (<ExceptionType>); skipped`), so nothing is hidden. Optional improvement: exit 1 if any export failed.

**B3 — minor (cheap):** `docs/RUN-SHEET.md` says `DONE (PR pending)`, but PR #1 is open. The run sheet's own status words say `DONE (PR #n)`, so this should read `DONE (PR #1)`.
