# T3-C1 — class 3H (Lifecycle for People and Service Accounts)

Repo: td-3-iam · Environment: td-3-iam · Day: D6 · Time box: 60 minutes · Credit cap: $5

## Goal
A lesson, not a build. The director walks Eojin through the 3H code until he can explain every part in an interview, then runs a "why" interview of ten questions, one at a time, grading honestly. One live-change exercise shows the test-first habit. The transcript summary and grades go to `docs/learning/T3-C1.md` so a hiring manager can see what Eojin understands, not just what the AI produced.

## Steps
1. Director: read the brief; confirm Needs; say the plan in two lines (walk-through order, then interview, then exercise); start when Eojin says go. No subagent is needed for the lesson itself (`builder` is not used in a class session; `chores` writes the learning note, `verifier` checks it); keep the main session's reading to one pass per file.
2. Director (teacher): walk through the code in this order, each step ending with "what would break if this were missing": `lifecycle/feed.py` (rows → dataclasses; strict booleans) → `lifecycle/engine.py` `plan` (diff first, then apply; idempotency) → the proofing gate and `reports/blocked-joiners.md` → `lifecycle/sod.py` and `sod-rules.yaml` → `lifecycle/attest.py` and `lifecycle/expiry.py` (injected "today") → `lifecycle/kc.py` (admin token flow, which REST calls exist and which deliberately do not, for example delete) → `tests/unit/` fakes versus `tests/integration/` marked `keycloak`. Explain each term the first time: joiner/mover/leaver, idempotent, realm, group, role, client, service account, attestation, separation of duties, identity proofing.
3. Director: run the live demo once: start Keycloak (T3-S02 step 2), `keycloak-dev.sh`, `plan`, `apply`, `apply` again (zero changes), `sod`, `attest`; show one attestation file.
4. Director (interviewer): ask the ten questions below **one at a time**. Wait for Eojin's answer. No hints before he answers. Grade each 0–2 (0 wrong or empty, 1 partly right, 2 right and explained) with one sentence on what was missing. Ask the next only after grading.
5. Live-change exercise (the only code change allowed in this session, besides a bug Eojin finds): "A leaver must be disabled within 24 hours of `end_date`; any leaver still enabled after that shows as `OVERDUE` in their manager's attestation file." The director writes the **failing test first** in `tests/unit/` (using the injected `LIFECYCLE_TODAY`) and shows it failing. Eojin dictates the implementation line by line in chat (the director may name the file and function, nothing more) and the director types exactly what he dictates; run the test until it passes; run `ruff check .` and `pytest -q`. Commit the implementation with `--author="Eojin Kim <ID+DK1051@users.noreply.github.com>"` (ID from `gh api users/DK1051 --jq .id`) and the message body "Dictated by Eojin in class; typed verbatim by Claude."
6. `chores`: write `docs/learning/T3-C1.md`: date, walk-through outline, each question with Eojin's answer summarised in his words, the grade and the one-sentence correction, the exercise result (test name, pass/fail), total score out of 20, and three things to revise.
7. `verifier`: check the acceptance criteria; write `docs/verify/T3-C1.md`.
8. Director: `wrap` (branch `t3-c1-class-3h`).

The ten "why" questions:
1. Why does the engine compute a plan first and apply afterwards, instead of changing Keycloak row by row while reading the CSV? Name one thing that goes wrong with row-by-row.
2. Why must `apply` be idempotent? Give one real situation at a credit union where the same HR feed is sent twice.
3. Why do we disable a leaver instead of deleting the account? Name two things that are lost on delete.
4. Why do all three verification fields (`id_checked_live_video`, `references_contacted`, `education_verified`) have to be true before a joiner is created? Which of the three would a Scattered-Spider-style caller find easiest to fake, and why?
5. Why is "requester ≠ approver" a separation-of-duties rule, and what exactly does it stop at Maple Harbour?
6. Why can nobody be in both `payments-initiate` and `payments-approve`? Describe the loss in money terms.
7. Why must every service account have an owner and an expiry date, and what usually happens to an ownerless service account after the person who created it leaves?
8. Why does the quarterly attestation go to the manager and not to IT? What does the manager know that IT does not?
9. Why does the engine read the Keycloak admin password from an environment variable instead of a config file in the repo, and why is `dev-only-not-secret` acceptable here but never in production?
10. Why do the unit tests use a fake Keycloak, and why do we still keep the `keycloak`-marked integration tests instead of choosing one or the other?

## Known caveats
- The class rule in `CLAUDE.md` ("change no code except a bug he finds") is relaxed for exactly one thing: the live-change exercise in step 5, with Eojin writing the implementation.
- Keycloak state is ephemeral; the demo needs the full start + `keycloak-dev.sh` + `apply` sequence (about 2 minutes).
- Grades are the AI's judgement and say so in the learning note; they are study feedback, not a certification.
