# T3-S01 — 3E scaffold + trial runbook

Repo: td-3-iam · Environment: td-3-iam · Day: D1 · Time box: 60 minutes · Credit cap: $5

## Goal
Scaffold the 3E Anti-Takeover Tenant project: the documents and the one read-only script Eojin needs to set up a trial Microsoft 365 / Microsoft Entra tenant (a "tenant" is one organisation's own copy of Microsoft's identity service) for the fictional Maple Harbour Credit Union, lock it against the helpdesk-reset takeover described in AL26-010, and record before/after evidence. This session writes documents and one PowerShell script only; it configures nothing. Everything that touches Microsoft happens later, on Eojin's own PC, with his own account.

## Needs (stop if any is missing)
- The kit files: `CLAUDE.md`, `.claude/agents/builder.md`, `chores.md`, `verifier.md`, `redteam.md`, `scripts/probe.sh`, `requirements.txt`, `.github/workflows/ci.yml` (jobs `checks` and `pwsh-lint`), `docs/RUN-SHEET.md`, `docs/CAVEATS.md`, `COSTS.md`, `AI-USE.md`.
- No merged session is required: this is the first Track 3 session.
- Eojin does not need to have started any trial; the runbook written here is what he follows afterwards.

## Steps
1. Director: read this brief; ask `chores` to run `bash scripts/probe.sh` and append the output to `docs/PROBES.md` under today's date. Note the `pwsh:` and `keycloak:` lines (if either says "not installed", add a caveat line now — it affects step 7 and T3-S02). Propose the plan in Plan mode; wait for approval.
2. `chores`: create the folder skeleton, each file with a one-line placeholder heading only:
   `3e-anti-takeover-tenant/README.md`, `TRIAL-RUNBOOK.md`, `CONFIGURE.md`, `controls.md`, `before-after-report.md`, `scripts/export-config.ps1`, `maester/README.md`, `export/.gitkeep` (the `export/` folder is already git-ignored in `.gitignore`; the `.gitkeep` must be force-added with `git add -f` or the folder is simply documented — either is fine).
3. `builder`: write `TRIAL-RUNBOOK.md` as a numbered checklist Eojin ticks on his own PC, in this exact order, with every step explained in one plain sentence (what the button does and why we do it):
   1. The Korea path: Microsoft's Korean site offers a free trial only for **Microsoft 365 Business Basic**, so start a Business Basic trial first. Say which account to use (a brand-new admin account on a brand-new tenant; never a personal mailbox) and that the tenant name must be fictional, with no personal data.
   2. In the Microsoft 365 admin centre, try to add a **Business Premium** trial or a **Microsoft Entra ID P1/P2** trial on top (P1 = the paid tier that unlocks Conditional Access and authentication strengths; P2 adds risk-based policies). Record which one was offered, if any, in `before-after-report.md`.
   3. **Day one, before anything else:** Billing → Your products → the subscription → turn **OFF** recurring billing, and buy nothing. Write exactly why: with recurring billing off, the trial ends instead of charging a card. If any screen asks how many licences to buy, it is a purchase screen: close it. (At trial sign-up, if asked how many licences you need, choose the smallest number offered.)
   4. Calendar reminders on **day 1** ("confirm recurring billing is OFF") and **day 25** ("export config, screenshots, then let the trial lapse"). Refunds are only possible within **7 days**, so the day-1 check is the real safety net.
   5. Fallback: if no P1 trial is possible, scope 3E to **Entra Free** features (sign-in logs, per-user MFA, security defaults) and mark in `controls.md` every control that needed P1 as "not configured — needs P1". The report is still valid; it just shows the licence boundary honestly.
   6. Hand-off note for Track 4: the Azure free account for `td-4-cloud` is created with this tenant's admin account, and only on the day 4E is configured — not earlier.
   7. Safety box at the top: never paste the tenant ID, the `.onmicrosoft.com` name, admin email, invoices or screenshots with IDs into this repo; blur or crop before committing screenshots.
   Everything in the runbook that depends on what Microsoft shows on the day (trial availability, menu names, refund window) gets a `TODO(verify on the day)` marker next to it rather than a claim.
4. `builder`: write `controls.md` as one table with columns **Control · What it stops (plain English) · Licence · OSFI B-13 §3.2.7 · Cyber Centre baseline control · AL26-010 recommendation**, one row for each of these eight controls, in this order:
   - passkeys / phishing-resistant MFA for all staff
   - authentication strengths (require phishing-resistant methods for admins)
   - Conditional Access: block legacy authentication
   - Conditional Access: require strong authentication for admins
   - Conditional Access: sign-in from a new device for privileged roles requires strong re-authentication
   - Temporary Access Pass (TAP) issued only after verified identity (out-of-band callback, per Track 1)
   - self-service password reset with strong methods only
   - two break-glass accounts (emergency admin accounts) excluded from Conditional Access, stored offline
   Rules for the table: the Licence column uses only **P1** (Conditional Access, authentication strengths), **P2** (risk-based), **Free** (sign-in logs) or **TODO(verify)** (TAP, passkeys, SSPR); the OSFI column quotes one of these five phrases verbatim, in quotation marks: "Enforcing the principles of least privilege, conducting regular attestation of access" / "Implementing MFA across external-facing channels and privileged accounts" / "Managing privileged account credentials using a secure vault" / "Logging and monitoring account activity" / "Ensuring system and service accounts are securely authenticated, managed and monitored"; the Cyber Centre column cites baseline control **#5 (strong user authentication)** or **#12 (access control)**; the AL26-010 column quotes the alert's wording from `README.md`. Add one sentence above the table: these controls are **aligned to** the cited guidance; the word "compliant" must not appear anywhere in the file. Add a short glossary under the table (Conditional Access, authentication strength, TAP, break-glass, legacy authentication, phishing-resistant).
5. `builder`: write `before-after-report.md` as a template: a header block (tenant: fictional name only; licence obtained; dates), then one section per control from `controls.md` with fields **Before** (setting value or screenshot file name) · **After** · **Evidence** (screenshot file name, blurred) · **Date** · **Needed P1?**, then a "Test accounts" section (fictional Maple Harbour staff: a standard user, an admin, two break-glass) and a "What I could not do and why" section.
   Then, also `builder`: write `CONFIGURE.md`, the click-path Eojin follows to switch the controls on: one numbered section per control in `controls.md`, in a safe order: (1) create the two break-glass accounts and store their passwords offline; (2) create every Conditional Access policy in **Report-only** mode, each excluding the break-glass accounts; (3) Entra admin centre → Overview → Properties → **Manage security defaults** → **Disabled** (security defaults block Conditional Access policies from being switched on); (4) switch the policies **On** one at a time, signing in as the test user after each one; then the remaining controls. Mark every menu path `TODO(verify on the day)`. No tenant names or IDs.
6. `builder`: write `scripts/export-config.ps1`, a **read-only** export of the tenant's identity configuration for the report. Requirements: a comment header that tells Eojin to run `Connect-MgGraph -Scopes Policy.Read.All,Directory.Read.All` on his own PC first; the script checks `Get-MgContext` and exits with that instruction if not connected — it never calls `Connect-MgGraph` itself; it uses only `Get-Mg…` cmdlets (expected: `Get-MgIdentityConditionalAccessPolicy`, `Get-MgIdentityConditionalAccessNamedLocation`, `Get-MgPolicyAuthenticationMethodPolicy`, `Get-MgPolicyAuthenticationStrengthPolicy`, `Get-MgDirectoryRole` with `Get-MgDirectoryRoleMember` — mark the exact cmdlet and module names `TODO(verify)` in the header, do not guess parameters that are unsure); it writes JSON files only into `3e-anti-takeover-tenant/export/` (git-ignored), with a warning that the files contain tenant and object IDs and must stay local; it never writes to the tenant (no `New-`, `Set-`, `Update-`, `Remove-`, `Add-` cmdlets, no `Invoke-MgGraphRequest`); it prints a one-line summary count per export.
7. `builder`: syntax-check the script with PowerShell's own parser (no modules needed, works offline):
   `pwsh -NoProfile -Command '$t=$null;$e=$null;[System.Management.Automation.Language.Parser]::ParseFile("3e-anti-takeover-tenant/scripts/export-config.ps1",[ref]$t,[ref]$e) | Out-Null; if ($e) { $e; exit 1 } else { "parse OK" }'`
   PSScriptAnalyzer cannot run here (PowerShell Gallery is blocked); the `pwsh-lint` CI job runs it on the pull request. If `pwsh` is missing, record a caveat and leave both checks to CI.
8. `chores`: write `maester/README.md`: three short paragraphs — what Maester is (an open-source test suite for Entra settings), that it runs in GitHub Actions with OIDC per https://maester.dev/docs/monitoring/github, and that the setup is Eojin's and optional (not part of any session's acceptance criteria). No workflow is created in this session.
9. `builder`: write `3e-anti-takeover-tenant/README.md` with the five required sections (what it does, how to run it, what Eojin did vs what Claude did, results, limits); results say "not yet configured". Update the repo `README.md` status line and the 3E row to "Scaffolded — Eojin is configuring the tenant".
