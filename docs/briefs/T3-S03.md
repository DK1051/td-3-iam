# T3-S03 — 3H attestation, separation of duties, proofing gate

Repo: td-3-iam · Environment: td-3-iam · Day: D3 · Time box: 90 minutes · Credit cap: $10

## Goal
Finish the 3H lifecycle engine with the controls that make a stolen reset worthless. The **proofing gate**: a joiner is created only when all three identity checks in the feed are true. **Separation of duties (SoD)**: three rules that stop one person (or one unowned program) from holding a dangerous combination of access. **Attestation**: a quarterly Markdown report per manager listing every person and service account they are responsible for, with keep/revoke boxes, plus warnings for service accounts about to expire. Then the project README with a diagram.

3. `chores`: extend `hr/hr-feed.csv` with 4 rows that exercise the new rules: a joiner with `id_checked_live_video=false`, a joiner with `references_contacted=false`, a joiner with `education_verified=false`, and a mover whose new job title maps to `payments-approve` while they already hold `payments-initiate` in the seeded directory (reuse a T3-S02 mover who holds it; if none does, add one pre-existing Payments Officer to `keycloak-dev.sh` and the unit fake and list that change in the PR). T3-S02's tests read their own fixture copy, so extending this feed doesn't break them. Add one service account row with an empty `owner`. Add a row where `requested_by` equals `approved_by`. Keep `hr/fixtures/clean-feed.csv` as a copy of the T3-S02 feed with no violations, for the "clean" tests.
4. `builder`: proofing gate in `lifecycle/engine.py`: a joiner with any of `id_checked_live_video`, `references_contacted`, `education_verified` not `true` produces a `Blocked` entry in the plan (`BLOCKED joiner <employee_id>: proofing incomplete — <missing checks>`), is never created, and is written to `3h-lifecycle/reports/blocked-joiners.md` by `apply`. The gate also applies to `requested_by == approved_by` for every joiner and mover row (`BLOCKED …: requester equals approver`). Unit tests: three single-false cases, the all-true control case, the requester-equals-approver case.
5. `builder`: `3h-lifecycle/sod-rules.yaml` with exactly three rules, each with `id`, `title`, `plain_english`, `check`:
   - `SOD-1` requester ≠ approver for every access change
   - `SOD-2` no user in both `payments-initiate` and `payments-approve`
   - `SOD-3` no service account without an owner (`owner` attribute present and equal to an active employee)
   `lifecycle/sod.py` evaluates SOD-1 against the feed and SOD-2 and SOD-3 against the projected state: the current directory (through `kc.py` or the fake) plus the changes the feed would make, so a conflict is reported before `apply`. It returns a list of violations with rule id, subject and plain-English reason. The engine refuses to apply any action that would create a SOD-2 violation (fail closed: the mover is skipped and reported, not half-applied). CLI: `python -m lifecycle sod …` prints violations and exits 1 if any; 0 otherwise. Unit tests: one violation per rule detected; the clean fixture gives zero.
6. `builder`: `lifecycle/attest.py` — `python -m lifecycle attest --quarter 2026-Q4 --out 3h-lifecycle/reports/attestation/` writes one Markdown file per manager (`<manager_id>.md`): a header (manager, quarter, generated date), a table of direct reports (employee, job title, groups, enabled?) with `[ ] keep  [ ] revoke` per row, a table of service accounts they own (client id, purpose, expires_on, status) with the same boxes, and a "Warnings" list. `lifecycle/expiry.py` flags a service account as `EXPIRES SOON` when `expires_on` is within 30 days of "today" and `EXPIRED` when past; "today" is injected (parameter or `LIFECYCLE_TODAY` env var) so tests are deterministic. The warnings also print in `attest` and `plan` output. Unit tests with a fixed date: one soon, one expired, one healthy, disabled users shown as disabled, an ownerless service account appears under "Warnings" of no manager and in SOD-3.
7. `builder`: run `ruff check .`, `pytest -q`, and `pytest -q -m keycloak` with the server up (integration: the three blocked joiners are absent from Keycloak, the SOD-2 mover was not applied, the attestation files exist, one per manager in the feed).

Update the repo `README.md` 3H row to "Built (T3-S02, T3-S03) — class pending".

## Known caveats
- Attestation decisions are read by a human; the engine does not apply "revoke" automatically (that would need a signed approval, which is the 3A problem).
- Keycloak state is lost with the session; every integration run starts from `keycloak-dev.sh` + `apply` (T3-S02 caveat).
- Unmanaged user attributes must be enabled on the realm (T3-S02 caveat) or the attestation tables will show empty job titles.
- "Today" for expiry is injected; wall-clock use anywhere in the tests would make them flaky.
